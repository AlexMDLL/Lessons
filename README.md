# Lessons — репозиторий по предмету

Один репозиторий = один предмет. **Одна пара = одна ветка** с именем `lesson_N`.

## Как устроено

| Ветка | Что внутри |
|---|---|
| `main` | шаблон: только этот README, `.gitignore`, `.gitattributes`, `LICENSE`. Кода пары здесь нет |
| `lesson_7`, `lesson_8`, ... | проект одной пары: `.sln`, `.csproj`, исходники — прямо в корне ветки |

Ветки **не сливаются** между собой: каждая ветка — самостоятельная тема со своим проектом.

## Как создать новую пару в Visual Studio

1. Переключитесь на шаблон: **Git → Manage Branches** → двойной клик по `main`, затем **Pull** (стрелка вниз), чтобы взять актуальный шаблон.
2. **Git → New Branch** → имя `lesson_8`, *Based on*: `main` → **Create**.
3. Создайте проект: **File → New → Project** → Console App, папку решения укажите внутри рабочей папки репозитория.
4. **Git Changes** → напишите описание коммита → **Commit All** → **Push** (стрелка вверх).

## Как создать новую пару в командной строке

```powershell
git checkout main
git pull
git checkout -b lesson_8        # новая ветка от шаблона

# ... создаёте проект и пишете код ...

git add -A
git commit -m "lesson_8: краткое описание темы"
git push -u origin lesson_8
```

## Правила

- **Секреты не коммитим.** Пароли и строки подключения — в файл `db.local.txt` рядом с `Program.cs` (он в `.gitignore`). Образец — `db.local.example.txt`.
- `.gitignore` уже исключает `bin/`, `obj/`, `.vs/`, `packages/` — эти папки в репозиторий не попадают и пересоздаются при сборке.
- Новая пара — всегда **новая ветка от `main`**, а не продолжение прошлой.
- Перед началом пары: `git checkout main` + `git pull`.

## Полезные команды

```powershell
git status                 # что изменено
git branch                 # список локальных веток
git branch -a              # + ветки на GitHub
git checkout lesson_7      # переключиться на другую пару
git log --oneline -5       # последние коммиты
git pull                   # забрать изменения с GitHub
git push                   # отправить свои коммиты на GitHub
```

## lesson_8 — Центр управления космической станцией (WPF + MVVM)

Проект пары: `WpfApp26.sln` — WPF, .NET Framework 4.7.2, паттерн MVVM.

| Файл / папка | Назначение |
|---|---|
| `VM.cs` | ViewModel: состояние ЦУП, команды, асинхронные проверки |
| `BC.cs` | простая реализация `ICommand` (как в предыдущих работах) |
| `Models/` | `CrewMember`, `StationSystem`, `StationMessage`, `DiagnosticLine`, `NavItem` |
| `Data/` | доступ к БД: `DbProvider`, `NpgsqlProvider`, `Db` (фабрика), `StationRepository` (запросы) |
| `Styles/Theme.xaml` | тёмная тема и стили контролов |
| `Views/` | шесть страниц: экипаж, системы, связь, сообщения, полная диагностика, аварийный режим |

Доступ к базе идёт **через фабрику провайдера**, как в уроке 7:
`App.config` регистрирует Npgsql в разделе `DbProviderFactories` → `Db.GetFactory()` берёт
`DbProviderFactory` по имени провайдера → подключение, команда и параметр создаются методами
фабрики. Поэтому код в `StationRepository` работает с `DbConnection`, `DbCommand`, `DbDataReader`
и не знает, какая именно СУБД подключена. Своя строка подключения — у провайдера
(`NpgsqlProvider.GetConnectionString`), своя подсказка по ошибке — тоже у него.

Порядок работы:

1. **Визуальная часть (готово).** Интерфейс полностью собирается и работает на демонстрационных
   данных: вместо запросов к БД стоят `Task.Delay`, поэтому видно, как идут три параллельные проверки.
2. **Внутренняя логика.** Асинхронный доступ к БД через фабрику провайдера: `OpenAsync`,
   `ExecuteReaderAsync`, `ReadAsync`, `ExecuteNonQueryAsync`, параллельная диагностика через `Task.WhenAll`.

**Строка подключения** хранится только в `db.local.txt` рядом с `WpfApp26.csproj`
(файл исключён в `.gitignore`). Образец — `db.local.example.txt`.

Скрипт создания таблиц `crew` и `station_systems` с данными — `db/lesson8_schema.sql`
(запускать повторно безопасно: данные добавляются только в пустые таблицы).

Запуск: открыть `WpfApp26.sln` в Visual Studio и нажать F5.

Что соответствует заданиям урока:

- задание 1–2 — раздел «Экипаж» (список, поиск по имени);
- задание 3 — панель операций: урон, восстановление, смена статуса;
- задание 4 — «Состояние систем», «Проверить связь», «Сообщения станции», «Полная диагностика»;
- задание 5 — «Аварийный режим».
